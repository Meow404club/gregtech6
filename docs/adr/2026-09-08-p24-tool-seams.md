## 0. 摘要

GT6 file/saw 工具移植一次立三缝：本仓首例 vanilla crafting RecipeProvider（GT6CraftingRecipes）、首例 TagsProvider（GT6ItemTags，takeover 链源头）、container-item 损耗通道。核心教训（id410→id413）：crafting 容器件通道类特性必须 Recipe.getRemainingItems 直调探针——静态缝测试结构性测不到 dispatch 门死锁（has 未覆写事故全程）。损耗 512 轴 1 点/次=声明偏离的归一。//? 分叉收敛到最小面（构造器签名/buildRecipes）。

## 1. 三缝定案

### 1.1 缝一：首例 vanilla crafting RecipeProvider（decisions.p24-tool-system-recipe-provider-first）

- 形态=单文件 GT6CraftingRecipes extends RecipeProvider；//? 分叉仅限**构造器+buildRecipes 签名**：1.20.1 buildRecipes(Consumer<FinishedRecipe>) 抽象（RecipeProvider.java:108）+PackOutput 单参构造器；21.1 buildRecipes(RecipeOutput)（:127）+构造器(PackOutput, CompletableFuture<HolderLookup.Provider>)（:70）、run() final 化（:77）。builder 链（shaped :45/define(char,TagKey) :53/pattern :72/unlockedBy :81/save）双腿同名共享。挂 GT6DataGenerators.onGatherData(:33)。
- 范围修正：研究卡『2 配方』收窄为 1 条 spray_can_empty——食品罐（"fh"/"oP"，MultiItemRandomTools.java:239）需 hammer+bendingcylinder_small，本仓无此二物品，**不硬造不入池**待工具族卡（防越权注册）。
- 后裔：草卡 6+6 配方、螺丝刀 circuit 行、prefix 后续均 tail-append 同缝不自建平行（decisions.p24-recipe-seam-contract ①）。

### 1.2 缝二：首例 TagsProvider（decisions.p24-tool-system-tag-strategy）

- 工具 ingredient 全 tag 化：自建 #gt6:tools/file、#gt6:tools/saw（对位 OreDictToolNames.craftingToolFile:1867/craftingToolSaw:1864 的 snake tag 翻译规则）；材料自建 #gt6:redstone（两腿 ItemTags 均无 redstone_dusts 仅 REDSTONE_ORES :61/:88，ore 语义证伪 vanilla tag）、#gt6:plate_curved_tin（census 关闭：生成树 plate_curved_tin.json 实存+GTMaterialItems.java:208+OP.java:1249）。
- 生态双向挂：forge 腿 #forge:tools（Tags.java:405，无 saw/file 细分=自建正当）+21.1 腿 #c:tools（Tags.java:799/:923/:280）；crowbar/cutter/chisel 三件同批回填。
- GT6ItemTags 以 takeover 缝交付（skeleton 卡接手扩展，详见 ADR-P24 tags-provider 范式篇，本篇不重复）。

### 1.3 缝三：container-item 损耗通道（decisions.p24-tool-system-damage-mapping)

- 钩子=覆写 getCraftingRemainingItem(ItemStack)（签名双腿一致：forge IForgeItem.java:195 / 21.1 IItemExtension.java:193，覆写无需 import Forge 类）——copy→setDamageValue(+1)，≤maxDamage 返回副本、>maxDamage 返回 ItemStack.EMPTY=工具消耗。上游先形=GTCEu IGTTool.java:530-554（含 Forge PR #3388 语义：PlayerDestroyItemEvent 不触发）。
- **损耗归一=声明偏离**：上游 file=400/saw=100 units（4:1 比率，GT_Tool_File.java:51-53），本仓 512 单级耐久轴恒扣 1 点/次——非整数比率且两工具失衡，故归一；对齐 P9 crowbar『1 vanilla point per 10000 upstream units』既有语义（GT6Tools.java:64-65 javadoc）。否决按比率折算与引入上游 unit 耐久轴（自定义耐久标量=体量失控，与 P9/P10 单级先例冲突）。

## 2. 死门事故与探针方法学（id410→id413，承重级教训）

### 2.1 事故全程（remember id410，S1 审查打回）

coder 只覆写 get，未过 dispatch 门：双腿合成循环 patch 同形（forge patches/.../Recipe.java.patch 与 neoforge 21.1 同）先调 item.hasCraftingRemainingItem()→默认体第一行 `if(!has) return EMPTY`→vanilla Item.craftingRemainingItem 字段判空恒假→**get 永不被调**：真实合成中工具整只被吞、1 点/次损耗缝是死码。本卡静态缝测试（FileSawTest 钉 craftRemaining 静态断言）/runData/runServer 注册冒烟**结构性测不到**此死锁——断言前提建错类。最小修法：两物品类 @Override hasCraftingRemainingItem(ItemStack){return true;}（双腿同名零 //?；GTCEu IGTTool.java:530-549 has+get 成对先例入 javadoc）；返工 de2fa4ef 合入 a95d9573。

### 2.2 探针方法学（id413 正典化）

- **直调探针**：匿名 Recipe 直调 default Recipe.getRemainingItems——即 forge patch 循环体本体（has 门→get），**穿门非绕门**，与服务器真实 dispatch 逐行同形；负例由构造保证（剥 has 覆写→vanilla 字段判空→残留 EMPTY→首断言必红）。
- 断言面：残留非空+assertSame+耐久 +1+原栈不动+侧格全空；saw 臂 510→511 贴严格大于消耗边界。
- 探针工程细节：holder 墙反射开窗——forge 腿三锁（vanilla frozen/ForgeRegistry.isFrozen/NamespacedWrapper.locked 藏父类需沿链 getDeclaredField）、21.1 腿单 frozen；探针物品须真注册（ItemStack ctor 急解析 delegate，未注册炸 "No delegate exists for value air"）；21.1 匿名 Recipe 需 getType()（抽象）不需 getId()（移除到 RecipeHolder）；CraftingInput 分叉=21.1 Recipe 重型化 <T extends RecipeInput> 的必要源码侧分叉。
- **合同化**：此探针成为后续容器件通道类特性（螺丝刀卡等）的验收强制件。

## 3. //? 分叉最小面模式

- 单文件足够：双腿各写一个 provider 类被否（分叉面过大）；分叉收敛到构造器签名/buildRecipes 两处。

## 4. 后裔缝：circuit 行产出带 Damage tag（decisions.p24-screwdriver-result-recipe）

vanilla shaped JSON 不可携带 NBT：`tmp/vanilla-1.20.1/net/minecraft/world/item/crafting/ShapedRecipe.java:272-283` itemStackFromJson 对 "data" 字段直接抛 "Disallowed data tag found"（抽验证实）。故电路配方行（产出带 Damage tag=GT6Circuits.java:61 TAG_CONFIGURATION，经 :111 selector(n)）用**自定义 Recipe 族一次成型**：GT6CircuitRowRecipe（shaped，覆盖 config1-24）+重置行 shapeless 同族+唯一 GT6CircuitRowSerializer 一次注册（DeferredRegister→RECIPE_SERIALIZERS），JSON result 用 configuration:int 字段。否决：包装 vanilla serializer（coremod 红线）、运行时注入 RecipeManager（21.1 Recipe 重型化分叉失控+离线不可测）。消解测性：vanilla Ingredient.test 只比 getItem() 物品身份（Ingredient.java:58-64）→通配输入零自定义 Ingredient。

## 5. 后果

- 正面：三缝一次成型后所有 vanilla crafting/tag 后续卡零新增基建（草卡/skeleton/prefix/circuit 全 tail-append）；损耗通道离线可测（探针=验收合同件）；教训已蒸馏为可执行纪律（has/get 成对+直调探针+else 注释腿）。
- 义务：coders 触碰 IForgeItem 拓展点必须成对覆写并自证探针红绿；验收链含双腿 cleanTest XML 实数+runData 二跑 written:0+runServer 冒烟（本卡 GATE_EXIT 124 为自设护栏非失败）。
- 声明偏离与不搬清单：512 轴 1 点/次（对齐 P9 语义）；PlayerDestroyItemEvent 不触发（Forge PR #3388，池注记）；食品罐配方/Robot Tip 无损件生态/file·saw 世界交互臂均不入（另卡/不搬）。
